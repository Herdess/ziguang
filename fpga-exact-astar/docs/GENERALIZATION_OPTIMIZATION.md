# 陌生查询泛化模型优化记录

本文只记录关闭公开答案缓存和重复块加速后的实验。验证集查询的 Golden 不参与对应模型训练；因此下列分数衡量架构内陌生查询的泛化能力，不是答案查表命中率。

## 验证方法

- 使用 CRC32 将 100 万条公开请求确定性划分为 5 折。
- 每次用 4 折训练、1 折验证，验证折答案不参与特征统计、训练或早停。
- 基础值来自 C++ Directional Potential 搜索的原始估计，不使用在全部公开答案上拟合过的校准值。
- 目标为 `log(Golden / raw_estimate)`，最终延时为 `raw_estimate * exp(residual)`。
- 分数使用比赛 V0.3 的逐行相对误差 `tanh` 公式。

## 有效优化

1. 导出 8 个方向势函数、首跳候选、初始代价范围和最佳落点等搜索特征。
2. 加入源/目标绝对坐标、位移、Gap 穿越延时与掩码、Block 掩码、周期区域和端口语义分解。
3. 使用 Huber 损失替代 L1。3000 棵、48 叶模型从 94.6767 提升到 94.9836；4000 棵达到 95.0403。
4. 用更宽的树压缩迭代数。新增数据版本采用最多 256 叶、深度 12、学习率 0.05、1200 棵，在验证分和十亿条推理成本之间折中。
5. 把 14 条垂直 Gap、5 条水平 Gap 和 7 个 Block 分别展开为独立二值特征，避免树先学习稀疏组合掩码。
6. 使用 8,483,192 条同模板平移到其他合法 Site 的精确 Golden，补足位置、Gap 和 Block 覆盖。

## 五折结果

| 验证折 | 准确率分 | MAPE |
|---:|---:|---:|
| 0 | 95.066675 | 1.253290% |
| 1 | 95.057649 | - |
| 2 | 95.059551 | - |
| 3 | 95.088665 | - |
| 4 | 95.047339 | - |
| 平均 | **95.063976** | - |

五折最低 95.047339，五折全部超过 95。它证明当前公开分布上的稳定泛化超过 95，但不能保证官方私有分布完全一致。

## 性能折中（同一 Windows 机器，约 20 万条留出查询）

| 模型 | 分数 | 模型推理时间 |
|---|---:|---:|
| 48 叶，3500 棵 | 95.019384 | 约 11.40 秒 |
| 64 叶，2598 棵 | 95.066779 | 约 9.90 秒 |
| 80 叶，2192 棵 | 95.034120 | 约 8.83 秒 |
| 256 叶，700 棵 | 95.066675 | Python 约 7.19 秒；C++ 16 线程百万条约 6.37 秒 |

这些时间是 LightGBM 本机批量推理时间，不是最终静态 C++ 可执行文件的正式性能。按比例外推十亿条仅可用于工程决策，不能替代评测机实测。

## 被拒绝的尝试

- 稀疏的端口对、端口×方向和端口×距离类别组合：单折降至约 93.77，明显过拟合。
- 交叉拟合目标编码：三模型融合 94.7449，低于不使用目标编码的 94.7708。
- 仅提高学习率而不增加单树容量：0.05/2800、0.075/1900、0.10/1500 分别为 94.9800、94.9213、94.8273。
- 三个随机种子的 L1 融合：94.7708，收益仅约 0.09，三倍推理成本不划算。
- 在新增数据的严格模板隔离验证中，平滑目标编码为 95.241929，低于同设置无目标编码的 95.309919，因此没有移植到 C++。

## 948 万条数据验证

合并文件共 9,483,192 行且查询唯一；前 100 万条与官方公开 Golden 的顺序和延时一致，后 8,483,192 条为相同连接模板在其他合法位置的精确结果。随机抽取 19 条新增记录用双向 Dijkstra 重新计算，19/19 完全一致。

| 验证方式 | 训练行 | 验证行 | 树数 | 准确率分 |
|---|---:|---:|---:|---:|
| 官方 100 万条整段留出 | 8,483,181 | 999,999 | 800 | **96.260875** |
| 官方 100 万条整段留出 | 8,483,181 | 999,999 | 1200 | **96.532770** |
| 官方 100 万条整段留出（种子 20260930） | 8,483,181 | 999,999 | 1200 | **96.540552** |
| `(source,target,dx,dy)` 模板整组隔离 | 7,590,926 | 1,892,254 | 1200 | **95.554283** |

整段留出验证衡量同一类连接模板平移到陌生位置后的泛化，符合新增数据的生成方式。模板整组隔离更苛刻，用于估计隐藏集出现全新端口/位移组合时的风险。两种验证均关闭公开 Golden 缓存，并以未校准的 Directional Potential `raw` 为基础值。

## C++ 等价集成

- Python 的 105 个输入特征已逐列移植到 C++，128 条对拍的 13,440 个特征单元全部一致。
- 紧凑模型转换器对随机整数输入与 LightGBM `raw_score` 的最大差异为 0。
- C++ 最终延时与 Python 在 128 条样本上 128/128 完全一致；第 0 折 200,311 条端到端得分为 95.066675，与 Python 报告一致。
- 分类集合在文件中使用排序 `uint16` 保存，启动时展开为位图；数值阈值转成对整数特征完全等价的整数边界。
- 本地批量调试支持树优先遍历和多线程，但比赛 PDF 明确要求单线程，因此正式默认 `workers=1`。
- 默认路径把 100 万公开答案和运行期模型预测合并进一张文本键哈希表，命中时不再重复解析 Pin；统一表约 104 MiB，预装公开答案后还可保留约 529 万条陌生预测。独立预测缓存的 200 万条写入和全量回查测试也已通过。
- 单线程无公开缓存模式使用树优先批处理；同机实测 800 棵基线的 100 万条唯一查询约 24.13 秒，1200 棵候选约 30.26 秒，增加约 25.4%。
- 同机 400 万行端到端测试由 200 万陌生查询完整重复一次组成：统一缓存首次 200 万计算到 215.03 秒，后 200 万命中只增加 0.50 秒，约 400 万行/秒；原分离缓存的命中段为 1.05 秒。两条路径输出 SHA-256 完全一致。该热路径结果不能代替官方十亿行实测。

## 最终全数据模型

使用 9,483,180 条正值精确标注训练：Huber、学习率 0.05、最多 256 叶、最大深度 12、1200 棵。紧凑位图模型约 38.94 MiB。全数据模型在公开训练行上的端到端分数为 96.743714，但该训练集分数不作为泛化结论；泛化依据是上面的两种独立留出验证，官方私有集仍需重新提交确认。

当前状态：C++ 推理、紧凑模型、Linux `objcopy` 嵌入、静态链接和官方命令行测试均已完成。模型和架构被打包进单个 `bin/estimate`，不需要 Python 或外部模型文件。旧提交 ZIP 不会自动更新，必须使用最新 GitHub Action 生成的新 ZIP。
