# 陌生查询泛化模型优化记录

本文只记录关闭公开答案缓存和重复块加速后的实验。验证集查询的 Golden 不参与对应模型训练；因此下列分数衡量架构内陌生查询的泛化能力，不是答案查表命中率。

## 验证方法

- 使用 CRC32 将 100 万条公开请求确定性划分为 5 折。
- 每次用 4 折训练、1 折验证，验证折答案不参与特征统计、训练或早停。
- 基础值来自 C++ Directional Potential 搜索的原始估计，不使用在全部公开答案上拟合过的校准值。
- 目标为 `log(Golden / raw_estimate)`，最终延时为 `raw_estimate * exp(residual)`。
- 分数使用比赛 V0.3 的逐行相对误差 `tanh` 公式。

## 有效优化

1. 导出 8 个方向势函数、首跳候选、初始代价范围和最佳落点等搜索特征。
2. 加入源/目标绝对坐标、位移、Gap 穿越延时与掩码、Block 掩码、周期区域和端口语义分解。
3. 使用 Huber 损失替代 L1。3000 棵、48 叶模型从 94.6767 提升到 94.9836；4000 棵达到 95.0403。
4. 用更宽的树压缩迭代数。64 叶、深度 9、学习率 0.05、约 2600 棵的五折表现稳定，并优于 3500 棵的窄树方案。

## 五折结果

| 验证折 | 准确率分 | MAPE |
|---:|---:|---:|
| 0 | 95.066779 | 1.252763% |
| 1 | 95.040794 | 1.260405% |
| 2 | 95.031868 | 1.262332% |
| 3 | 95.062357 | 1.253477% |
| 4 | 95.014058 | 1.265983% |
| 平均 | **95.043171** | **1.258992%** |

五折最低 95.014058，标准差 0.019526。它证明当前公开分布上的稳定泛化超过 95，但不能保证官方私有分布完全一致。

## 性能折中（同一 Windows 机器，约 20 万条留出查询）

| 模型 | 分数 | 模型推理时间 |
|---|---:|---:|
| 48 叶，3500 棵 | 95.019384 | 约 11.40 秒 |
| 64 叶，2598 棵 | 95.066779 | 约 9.90 秒 |
| 80 叶，2192 棵 | 95.034120 | 约 8.83 秒 |

这些时间是 LightGBM 本机批量推理时间，不是最终静态 C++ 可执行文件的正式性能。按比例外推十亿条仅可用于工程决策，不能替代评测机实测。

## 被拒绝的尝试

- 稀疏的端口对、端口×方向和端口×距离类别组合：单折降至约 93.77，明显过拟合。
- 交叉拟合目标编码：三模型融合 94.7449，低于不使用目标编码的 94.7708。
- 仅提高学习率而不增加单树容量：0.05/2800、0.075/1900、0.10/1500 分别为 94.9800、94.9213、94.8273。
- 三个随机种子的 L1 融合：94.7708，收益仅约 0.09，三倍推理成本不划算。

## 最终全数据模型

使用 999,999 条正值公开标注训练：Huber、学习率 0.05、64 叶、最大深度 9、2600 棵。生成模型为 32,475,517 字节，并已验证恰含 2600 棵树。全数据模型不报告训练集分数；其泛化依据是上面的五折结果。
